PHAROS-Rx

Pharmacovigilance Agent for Retrieval-Ordered Synthesis — a lighthouse, not a prescription.

Cohort-grounded retrieval-augmented synthesis over 215,063 real patient drug reviews, built to answer a question standard RAG cannot: is the evidence you retrieved representative of the population you claim to be summarising?

The problem

Retrieval-augmented generation over an opinion corpus inherits a bias that has nothing to do with retrieval quality. Similarity search returns the passages most similar to the query — in patient narratives, the ones that discuss it most emphatically. The model then reports that skew faithfully.

Every citation is real. Every sentence is grounded. The answer is still wrong about the world.

This project names that failure — retrieval-induced valence skew — measures it, and fixes it architecturally. A real cohort from the corpus:

A model reading only the conventional panel would report a gloomier picture than the data supports — with perfect citations.

The control that matters

Equal quotas per stratum (“uniform strata”) is twice as bad as doing nothing on cohort rating error (1.301 vs 0.667, p < 0.001) while scoring a perfect 1.000 on coverage. Matching the cohort, not just covering it, is what works.

Reported, not buried

The naive baseline beats PHAROS on nDCG and recall. Reserving panel slots for minority outcomes means admitting slightly lower-ranked units — a trade the project argues is worth taking, and shows openly.

What is new here

  1. Stratified Evidence Sampling — retrieval treated as sampling from a population: panel slots are apportioned across outcome strata to match the cohort's true distribution.
  2. Two metrics standard IR does not measure — VSD and CRE quantify how unrepresentative a retrieved panel is, and how many stars a reader would be misled by.
  3. The model never produces a number — Wilson intervals, PRR, ROR, χ² and IC are computed deterministically and handed to the model pre-formatted with verifiable IDs.
  4. Claim-level verification that catches disguised quantity claims such as “most reviewers report insomnia”.
  5. Data forensics — 10.3% of this widely used public dataset carries an undocumented character-deletion defect (below).

A defect in a heavily used public dataset

The UCI ML Drug Review dataset (Gräßer et al., 2018; 215,063 Drugs.com reviews) is widely used raw. pharos audit-labels shows 175 labels covering 22,089 rows (10.3%) are corrupted — for example 'Bipolar Disorde' (5,604 rows) and 'ibromyalgia' (2,370 rows).

The proof is structural: of 917 distinct condition labels, exactly zero end in “er” — impossible by chance in a vocabulary containing Cancer, Ulcer, Fever and Disorder. It matters because retrieval filters on condition: a question about bipolar disorder would otherwise match none of its 5,604 reviews.

Architecture

The shape is the argument: refusal precedes retrieval, statistics precede generation, and verification follows it.

Safety and engineering

Refuses what it shouldn't answer

Asked “should I stop my sertraline?”, the system could assemble a fluent, well-cited answer — which is exactly why it refuses. Triage is rules-first, so a refusal never fails open when an API is down.

42/42 red-team probes pass across 7 hazard categories, including 8 benign look-alikes that must not be refused.

Built to be reproduced

  • 253 tests on an in-memory synthetic corpus
  • CI: ruff · mypy · pytest on Python 3.10–3.12 · red-team suite
  • Config fingerprints on every artifact; seeded throughout
  • No API key, model download or GPU needed to reproduce every number

What is not claimed: relevance judgements are derived from corpus metadata, not human annotation; no statistic here is a pharmacovigilance signal (these are self-selected reviews); this is not a medical device and gives no medical advice.

Run it

git clone https://github.com/ocansey/pharos-rx.git
cd pharos-rx
pip install -e .
make build          # fetch → clean → segment → index   (~6 min)
pharos ask "What side effects do people report on metformin for type 2 diabetes?"

Stack: Python · LangChain · LangGraph · scikit-learn · NumPy/pandas · pluggable language-model backend (optional).
